# 大肥鱼 2.0 迁移到 DSH

## 目标

DSH 负责 Agent 的长期会话、任务循环、工具编排、浏览器和电脑操作。大肥鱼自己的代码负责人格、关系、记忆、目标、主动性和权限策略。

AstrBot 处于过渡位置：继续承载已经稳定的 FF14、语音和 QQ 能力，通过本地 HTTP、WebSocket 或 MCP 暴露给 DSH。新功能不再依赖 AstrBot 专有的事件钩子。

## 分层

```text
DSH Agent Host
├── BigFish identity      人格、自我描述、说话风格
├── BigFish memory        短期、经历、事实、技能记忆
├── BigFish agenda        关注点、目标、主动任务和唤醒时间
├── BigFish policy        权限、冷却、确认和可回滚动作
├── DSH QQ bridge         QQ / NapCat 出入站
├── DSH browser-use       B站和其他网页的观察与操作
└── local capability API  FF14、语音、音乐等现有服务
```

## 迁移顺序

1. 在独立 DSH profile 中接入 QQ Bridge，保持现有 AstrBot 在线。
2. 将大肥鱼记忆、目标和主动性从当前 Python 插件抽成独立本地服务。
3. 把 FF14 查询和语音封装为 DSH 工具，先只读，再逐步开放写操作。
4. 接入 B站读取和浏览器会话，完成“发现 → 观看/转写 → 形成观点 → 草稿”的闭环。
5. 加入主动社交循环：观察群活跃度、成员关系、话题兴趣和冷却状态，决定是否开口。
6. 经过一段时间的并行验证后，再关闭 AstrBot 中被 DSH 替代的入口。

## 主动性循环

```text
事件 / 定时唤醒
  → 更新世界状态
  → 召回相关记忆
  → 评估关注点和目标
  → 选择观察、等待、回复或主动发起话题
  → 执行工具
  → 检查真实结果
  → 写入经历和技能记忆
```

主动行动必须有原因、冷却时间和停止条件。发帖、评论、退群、改群设置和其他对外影响动作进入确认队列。

## 分支约定

日常开发在 `dev` 分支。每次迁移一个能力都保留独立提交，并在 AstrBot 和 DSH 两边做回滚点。
